# The launch video (vertical, phone)

> The main launch piece is now the widescreen film for laptop and tablet,
> with its posters: see [launch-film.md](launch-film.md). This vertical cut
> stays for Reels, TikTok and Shorts.

`launch/nhako-tools-launch.mp4`: 58 seconds, vertical 1080 x 1920 at 30 fps,
H.264 + AAC stereo. Made for Reels, TikTok, Shorts and a Play Store listing.

It is styled like an Apple keynote film: SF Pro Display headlines that rise
word by word out of a blur, a small accent-coloured eyebrow above each one, an
iPhone that tilts, zooms and fans out in 3D on a plain off-white stage, and a
modern synth score. Colour is flat throughout: no gradients, no pixel type.
The one thing kept from NeraOS is its pixel butterflies, flying at three
depths. Every screen inside the phone is the real app.
Everything is generated by code in `launch/video/`, so it can be rebuilt
whenever the site changes.

## Where every claim comes from

Nothing on screen is invented. Each number is one the app printed, or a fact
the README already states and tests.

| Claim | Source |
|---|---|
| 50 tools, 24 of them PDF | `src/tools/registry.ts` (counted 2026-09-25) and the site's own "Search 50 tools" |
| 5.5 MB to 432 KB, under a second | The Compress image capture: the tool reported "Under 500 KB: 442,502 bytes, 432 KB" in 443 ms and 444 ms on two runs, on the 2400 x 1600 PNG that `capture.mjs` draws, and "5.5 MB" for the same PNG. The byte count is identical across runs; the time varies by machine, so the caption says "under a second" |
| RM 4,706.00 take-home | LHDN's worked example (RM 5,500, spouse working, three children), asserted in `e2e/malaysia.spec.ts` |
| Zero uploads, no account | The README's "Why it exists" and "Privacy, precisely" |
| Tools you have used work offline | `scripts/build-sw.mjs`: a tool page is cached the first time it is opened |
| Every phone screen | Real captures of the production build (`launch/video/shots/`). Only the iPhone, its status bar and the Home Screen are drawn |

## Style

- **Type:** SF Pro Display only, 700 for headlines at 82 px with slightly
  negative tracking and balanced line breaks, 500 for the grey line under
  them. No pixel font anywhere in the video.
- **Motion:** words rise 36 px out of a 16 px blur, 75 ms apart, on a
  quintic ease-out. The phone moves on cubic ease-in-out between poses kept in
  `timeline.mjs` (`POSES`), including two push-ins that land a detail at the
  centre of the frame. A veil in the stage colour keeps a zoomed phone from
  running under the headline.
- **Colour:** flat, from the site's own tokens. An off-white stage
  (`#fbfbfd`), headlines in `#1d1d1f`, secondary text in `#6e6e73`, and one
  accent, the site's `--pink-600` (`#c7009b`), for eyebrows, "Zero uploads."
  and the counted number. Dark mode swaps the stage for plain black and the
  accent for a lighter pink that holds contrast on it. The phone is a solid
  graphite frame with a thin light rim, the same as in the README banner. No
  gradient colours anywhere.
- **The NeraOS hint:** the pixel butterflies from `src/lib/butterfly.ts`, in
  their four colourways. Six small ones fly behind the phone, two between the
  phone and the words (kept below the caption band), and three large ones
  cross close to the lens, blurred like a shallow depth of field. On the end
  card three circle the icon.
- **The icon:** the real `public/icons/apple-touch-icon.png`, scaled by a whole
  8 px per pixel-art cell so it stays crisp, in a squircle with a soft shadow.

## The soundtrack

`launch/video/audio.mjs` synthesises it sample by sample: no samples,
recordings or licensed music, so it is safe to post anywhere.

- 120 BPM, Fmaj7, G, Em7, Am7 (IV V iii vi) one per bar, landing on C major for the end card.
- Pads: three detuned band-limited saws per note, through a two-pole low-pass that opens after the intro and closes for the breakdown.
- Plucks: sine arpeggios in eighths through a dotted-eighth ping-pong delay. A bell topline from the home scroll on.
- Sub bass and kick on every beat, with the pads and sub ducking under the kick; claps on 2 and 4 and soft off-beat hats from 8 s.
- A Schroeder reverb (four damped combs, two allpasses) on everything melodic.
- Interface sounds on every cue: a short tick for taps, filtered-noise swishes for page pushes, a two-note chime when the photo is done, a shimmer as the number counts down.
- Measured with ffmpeg `ebur128`: -13.6 LUFS integrated, -1 dBFS true peak in the WAV. The intro sits about 6.5 LU under the main section and the dark-mode breakdown about 5 LU under, on purpose.

There is no voice-over. Most vertical video is watched muted, so the words on
screen carry the story and the music carries the mood.

## Rebuilding it

Needs Node 22 (it imports `butterfly.ts` directly), Playwright's Chromium, SF
Pro installed locally for the render (it is the system face on a Mac), and
ffmpeg with libx264.

```bash
npm run build
```

```bash
PORT=4400 npm run preview
```

Then, in a second terminal:

```bash
npm run launch:video
```

That runs, in order:

1. `launch/video/capture.mjs` takes the phone screens from the preview server into `launch/video/shots/` (git-ignored), plus `taps.json`, the real on-screen position of every element the finger taps.
2. `launch/video/audio.mjs` writes `launch/video/out/soundtrack.wav`.
3. `launch/video/render.mjs` serves `scene.html`, calls `renderFrame(t)` for each of the 1,740 frames, screenshots it, and pipes the PNGs into ffmpeg with the soundtrack. About three minutes on Kim's machine.

Other modes of `render.mjs`:

| Command | Output |
|---|---|
| `node launch/video/render.mjs --stills` | Check frames in `launch/video/out/` |
| `node launch/video/render.mjs --stills 13.5,27.6` | Just those times |
| `node launch/video/render.mjs --serve` | A local URL; add `?play` to watch in real time with sound, or `?t=27.6` for one frame |
| `node launch/video/render.mjs --poster` | `launch/poster.png`, the end card at 56 s |
| `node launch/video/render.mjs --banner` | `docs/brand/banner.png`, the README banner |

To change the story, edit `timeline.mjs` (captions, screens, taps, camera
poses). To change the look, edit `scene.html` and `scene.js`. Rendering is
deterministic: time is passed in, never read from a clock, so the same inputs
give the same frames.
